## 上游兼容和数据库结论

当前未发现未处理的 SQL/Ent 字段或 Git 合并冲突。原上游 **286 份 SQL 文件**保持不变，只增加 `235_subscription_daily_reset.sql`。迁移执行器本身与上游一致，按完整文件名而非数字前缀识别，因此它与 `235_group_model_allowlist.sql` 可以同时执行。无需改名、删除历史迁移或改 checksum。

新升级测试先执行原上游迁移，再写入旧结构的用户、余额、API Key、分组模型白名单、订阅到期及三种用量，随后启动二开完整迁移。断言原字段整行数据及原迁移历史不变，新权限和自动开关默认关闭；重复迁移不覆写管理员/用户后来设置的偏好。

测试用文件集以 286 个文件及聚合 SHA256 固定到 `881f32026`：`0e603b72c87bfd1b7ad9a02625c56c5e212e37752fe298c942f5a43cec4b2f5f`。后续更新上游 SQL 时必须重新审查并更新基线，避免测试悄悄换成另一个上游版本。

新增并发/事务测试覆盖六路续费与付费重置并发的期限守恒、外层事务回滚（活跃/过期/暂停）、当天 100 次后过期续费不能绕过次数限制，以及锁等待取消后释放前置锁。没有发现需要修改仓储生产代码的新缺陷。

自然扫描可能更新数据库而不立即刷新旧展示缓存。已用耗尽的 L1 和 billing cache 回归确认：当前计费准入回读数据库，不会因此误拒绝。上游原有 `/v1/usage` 展示路径可能短暂显示旧用量，属原有缓存展示边界，本轮未重构此路径。
