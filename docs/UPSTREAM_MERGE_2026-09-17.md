## 确认的二次开发

依据 Git 差异、设计文档和源码，确定的产品定制是“获得分组许可的月卡订阅提前重置每日额度”。支付、生图、模型广场等功能已存在于上游基线，不能列为本地新开发。

1. 管理员创建或编辑订阅分组时设置 `allow_subscription_day_reset`，默认关闭；开启要求存在有限的正数日额度。
2. 用户可以手动重置有消费的每日额度，也可以自行开启、关闭自动重置。
3. 每次成功重置清零当日已用额度，同时减少恰好 24 小时有效期；扣减后必须仍未到期。
4. 每订阅每系统自然日最多成功重置 100 次。失败、重复请求、冲突及自然刷新不计次。
5. 自动重置仅在日额度耗尽时执行，覆盖开启后的即时检查、成功结算后的检查、请求准入检查，以及启动和周期性后台扫描；无需保持网页打开。
6. 周/月消费及历史记录保留；周/月额度耗尽时拒绝付费重置。有效期缩短后仍保持自然日刷新。
7. 未到期续费保留自动偏好，过期重新开通关闭偏好；调整暂停订阅的有效期不会解除暂停。
8. 同一订阅的多把 API Key 共享额度和次数；事务、版本号和幂等操作 ID 防止重复扣天。浏览器断线或刷新后核实原操作，不重新生成扣天请求。
9. 分组字段、Ent 实体、DTO、用户路由、计费触发、各协议准入和前端控件完整贯通；原记录 REV-01 至 REV-10 的修复均保留。

“月卡”在本项目中按订阅类型和管理员分组许可识别，不按套餐名称、价格或剩余天数推断。

完整业务规则见 [月卡每日额度重置功能](MONTHLY_SUBSCRIPTION_DAILY_RESET.md)。

## 合并处理

普通合并产生三处文本冲突，已逐项处理：

| 文件 | 处理方式 |
| --- | --- |
| `backend/ent/runtime/runtime.go` | 同时保留本地重置字段和上游模型白名单字段；依据合并后的 schema 完整重新生成 Ent，逐个 Go 文件比对一致。 |
| `backend/internal/service/subscription_service.go` | 保留续期行锁、过期重开初始化、自动偏好规则和暂停状态；兼容上游批量订阅操作的嵌套事务。 |
| `frontend/src/views/admin/__tests__/GroupsView.duplicate.spec.ts` | 同时保留月卡许可测试和上游简易模式、Codex manifest 测试。 |

订阅续期冲突解决期间，自动合并的 `return sub` 会返回修改前快照。现有续期测试实际复现失败，恢复事务后的仓储回读后通过；上游批量事务内的回读仍使用同一事务上下文。

全量验证还修正了精确的测试夹具，没有为通过测试删减业务断言：

- 前端渠道监控测试同步新增的 MiniMax/OpenCode Go 平台；Codex manifest 测试同步鉴权 store 和模型白名单 API。两项问题均在纯上游 `881f32026` 导出代码中复现。
- 后端 API 契约测试补齐二开新增的公开字段默认值，并覆盖许可、自动偏好和日历刷新标记为 true 时的响应。原月卡工作区亦可复现遗漏。
- 上游 Ollama 旧回调测试采用两个即时 `time.Now()+5s` 模拟不同冷却轮次，在 Windows 时钟精度下两者可能相等；改为从旧时间确定性地增加一秒，保持 CAS 拒绝旧回调的所有断言。

Windows 仓储测试使用的 `sh` 通过该测试进程的 PATH 提供，没有修改应用配置。Ent 生成遇到 Windows 文件映射占用后，改在工作区外的临时源码副本完成，再逐文件验证结果。
