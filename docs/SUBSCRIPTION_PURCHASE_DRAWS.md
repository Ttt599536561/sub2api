# 订阅套餐单笔支付赠送抽奖次数

月卡、周卡等人民币订阅订单成功完成后，按该笔订单实际支付金额每满 **50 元**赠送 **1 次**抽奖机会。

| 单笔实付 | 赠送次数 |
| --- | --- |
| 49.99 元 | 0 次 |
| 50 元 | 1 次 |
| 75 元 | 1 次 |
| 100 元 | 2 次 |
| 200 元 | 4 次 |

每笔独立计算。两笔 25 元均不赠送，两笔 75 元合计赠送 2 次；余数不跨单累计。

## 参与范围

- 使用订单保存的人民币实付金额及支付币种快照，其他币种不直接套用 50 元门槛。
- 只统计福利活动开放且未暂停时首次完成的付费订阅订单。历史已完成订单及首次开放前付款的订单不补发。
- 余额充值、后台赠送订阅、兑换码订阅和订阅额度内的 API 使用，不产生这类套餐赠送次数。
- 原有 API 实际账户余额消费每累计 $50 获得一次的规则继续生效。其美元消费进度与套餐人民币单笔金额独立计算，获得的整数次数可以共同使用。

## 退款

退款确认成功后，按原单剩余净实付重新计算赠送次数。例如 200 元订单赠送 4 次，退款 60 元后剩余 140 元，保留 2 次。处理中或失败的退款不回退次数。

已获得的福利余额保留。若抽奖次数已经使用，减少的权益会表现为待抵扣次数，后续获得的次数先抵扣欠额。退款回退不会额外向账户余额入账。

## 开启与升级

沿用后台“福利管理”的活动开关，无需再开启一个套餐开关。启用后，用户福利中心会同时显示套餐单笔赠送说明和 API 余额消费进度。

新增迁移 `240_welfare_subscription_rewards.sql`，添加独立的订单奖励记录和套餐净赠送次数；默认值为零，不回填历史订单，不修改 239 及其他历史迁移。

支付完成、赠送记录和次数更新共用数据库事务，并以订单号去重。退款成功状态、赠送回退及成功审计也在同一事务提交。网关已确认退款但本地收尾失败时，保存确认结果用于后续本地重试，避免重复退款或重复扣除订阅权益。

本地开发和自动化验证使用隔离数据库，不连接生产数据库、不发起真实支付或退款。
