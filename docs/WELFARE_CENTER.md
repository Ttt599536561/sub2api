# 福利中心

用户入口：充值与订阅下方的「福利中心」。管理员入口：「福利管理」。

## 启用与暂停

升级后会执行增量迁移 `239_welfare_center.sql`。福利发奖默认关闭，管理员在「福利管理」保存为开放后开始运行。

首次开放时间由数据库记录，只有此后的合格 API 实际余额结算计入消费进度；历史已结算费用不补发抽奖次数。重新开放不会重置首次开放时间、钱包、抽奖次数或签到记录。

暂停会停止新的签到奖励、抽奖和消费资格累计。已有福利余额仍可兑换，历史记录仍可查询。简易模式不提供福利功能。

## 已实现规则

- 福利余额独立于账户可用余额。签到、连续奖励和中奖先进入福利钱包，手动 1:1 兑换后才进入账户余额。
- 部分或全部兑换均可，最小货币单位 $0.01，无手续费。兑换不计充值总额、不触发邀请返利。
- 每日签到按北京时间换日，不补签；连续第 7／15／30 天额外奖励，30 天一轮，漏签重置轮内连续进度，历史累计天数保留。
- 日奖采用确认的 v2：普通奖励与惊喜奖励分支，连续三次普通日奖后，下一次成功签到必定进入惊喜分支。保护计数不因漏签或轮次变化清零。连续礼包奖励不影响日奖保护计数。
- 用户页面不提前展示签到金额范围或连续奖励金额，成功后才显示实际到账结果与流水。
- 上线后的 API 实际账户余额结算累计每满 $50 获得一次抽奖，余数保留。订阅额度内消费、充值、图片预冻结／释放不计入，图片最终 capture 按实际费用累计。
- 抽奖资格随扣费事务同步提交。福利页在可见时每 10 秒读取概览，失败退避；未完成或尚未结算的 API 请求稍后计入。
- 福利记录提供全部、每日签到、连续奖励、抽奖、兑换五个筛选选项及北京时间日期范围。

## 账务与恢复

福利奖励使用整数分，消费进度保留 PostgreSQL `NUMERIC(20,8)` 精度；金额 API 使用十进制字符串。对账事实、签到和操作结果为追加记录，原始事实禁止修改／删除。

签到按用户与业务日期唯一，抽奖与兑换按账户、类型及幂等键唯一。用户资金变更在一个数据库事务中提交，失败整体回滚；服务端重试返回已保存结果。

兑换报价使用福利余额专用版本。消费进度变化不会令报价失效，其他领奖或兑换导致福利余额变化时需重新报价。

账户入账后的计费缓存和 API Key 认证缓存立即尝试失效，失败由持久 outbox 重试。余额缓存回填使用版本校验，防止兑换前的旧读取回填覆盖新余额。

内部费用修正接口 `RefundWelfareUsageBalance` 必须在调用方的 SQL 事务中使用，并关联原消费、有效管理员、理由及幂等标识。它不提供用户退款入口。已消耗的抽奖次数不回滚，退款后不足的资格由后续消费抵扣；退款和普通充值退款不是同一业务。

## 验证与性能

推荐使用项目已有 pnpm 9（本次验证为 9.15.9），不因本功能升级依赖或改锁文件。

```powershell
# frontend
npx --yes pnpm@9.15.9 install --frozen-lockfile
node node_modules/vue-tsc/bin/vue-tsc.js --noEmit
node node_modules/vitest/vitest.mjs run
node node_modules/vite/bin/vite.js build

# backend；Windows 上较低并行度可以减少编译内存峰值
$env:GOMAXPROCS='2'
$env:GOGC='50'
# 既有备份测试调用 sh；Windows 使用已安装的 Git Bash。
$env:PATH='C:\Program Files\Git\bin;'+$env:PATH
go test -p 1 ./...
go test -p 1 -tags=unit ./...
go test -p 1 -tags=integration ./internal/repository -run 'TestWelfare|TestUsageBillingRepository' -count=1 -v
go build ./cmd/server
```

数据库集成测试需要 Docker，使用独立 PostgreSQL／Redis 容器，不应连接生产数据库。检查输出确认测试实际执行，不能把容器不可用导致的 skip 当作通过。

`TestWelfareBillingPerformanceSmoke` 对同一账户和多个账户分别运行关闭／开启福利时的结算，对比吞吐及 p50/p95/p99。它是本地小样本对比，不是生产承载能力保证。上线观察结算队列、数据库锁等待、WAL／IO、连接池和错误率，不能仅以接口平均响应时间判断影响。

关闭获奖开关可以停止新增奖励，但不会删除资金、历史记录或消费事实；不要用删除福利表的方式回滚已发生的活动。

本次验证结果、并发回归、页面对账及本地性能样本见 [开发与验证记录](WELFARE_CENTER_VERIFICATION_2026-09-19.md)。
