# 福利中心

签到/抽奖规则核对：2026-10-27，适用已发布的 `0.2.18-r2`，应用源码 `03eb8f3fc4a61729eb6a1525547a2f79b38b71f0`。当前公开规则为 v4：签到沿用 v3 小额奖励，抽奖使用 v4 奖池。源码、镜像和运行实例状态见[当前交接](HANDOFF.md#当前代码和发布状态)；已发布镜像不代表目标服务器已升级或福利活动已开放。

用户入口：充值与订阅下方的「福利中心」。管理员入口：「福利管理」。

## 启用与暂停

本节开关控制签到、抽奖和消费赠送次数；下方QQ邀请月卡使用独立的邀请接收及活动开关。

首次引入福利功能的迁移为 `239_welfare_center.sql`；新安装的福利发奖默认关闭，管理员在「福利管理」保存为开放后开始运行。后续新增迁移按数据库中未执行的记录依次应用，已有活动开关和首次开放时间保留。

首次开放时间由数据库记录，只有此后的合格 API 实际余额结算计入消费进度；历史已结算费用不补发抽奖次数。重新开放不会重置首次开放时间、钱包、抽奖次数或签到记录。

暂停会停止新的签到奖励、抽奖和消费资格累计。已有福利余额仍可兑换，历史记录仍可查询。简易模式不提供福利功能。

## 已实现规则

- 福利余额独立于账户可用余额。签到、连续奖励和中奖先进入福利钱包，手动 1:1 兑换后才进入账户余额。
- 部分或全部兑换均可，最小货币单位 $0.01，无手续费。兑换不计充值总额、不触发邀请返利。
- 每日签到按北京时间换日，不补签；连续第 7／15／30 天额外奖励，30 天一轮，漏签重置轮内连续进度，历史累计天数保留。
- 日奖采用 v3 小额奖励：普通奖励与惊喜奖励分支；此前连续普通日奖次数为 0／1／2／3 时，下一次成功签到进入惊喜分支的概率依次为 20%／30%／50%／100%。保护计数不因漏签或轮次变化清零，连续礼包奖励不影响日奖保护计数。具体金额、连续奖励分布与兼容规则见[签到 v3 变更记录](changes/2026-10-26-welfare-checkin-v3.md#新规则)。
- 用户页面不提前展示签到金额范围或连续奖励金额，成功后才显示实际到账结果与流水。
- 上线后的 API 实际账户余额结算累计每满 $50 获得一次抽奖，余数保留。订阅额度内消费、充值、图片预冻结／释放不计入，图片最终 capture 按实际费用累计。
- 人民币订阅套餐单笔实付每满 50 元另赠 1 次抽奖，余数不跨单累计；参与范围、退款与次数欠额见[套餐支付赠送说明](SUBSCRIPTION_PURCHASE_DRAWS.md)。
- 抽奖资格随扣费事务同步提交。福利页在可见时每 10 秒读取概览，失败退避；未完成或尚未结算的 API 请求稍后计入。
- 福利记录提供全部、每日签到、连续奖励、抽奖、兑换五个筛选选项及北京时间日期范围。

## 当前抽奖规则（v4）

每次消耗 1 次抽奖机会，不额外扣账户余额；每次独立且无空奖，不按累计抽数触发额外保底。

| 奖励 | 概率 |
| --- | --- |
| $0.01 | 45% |
| $0.02 | 30% |
| $0.05 | 18% |
| $0.10 | 5% |
| $0.20 | 1.5% |
| $0.50 | 0.4% |
| $1.00 | 0.1% |

单抽期望为 $0.0305，最高 $1；期望值不是逐次或逐用户承诺。奖池抽样与公开概率共用[后端规则](../backend/internal/service/welfare_rewards.go)，前端从 API 读取。公开规则版本为 4，新抽奖私有审计为 v4，签到私有审计仍为 v3；版本定义见[福利模型](../backend/internal/service/welfare.go)。

## QQ邀请月卡（NapCat）

管理员从“福利管理 → QQ邀请奖励”（`/admin/welfare`）进入“连接与扫码登录”或“活动与奖励”。该模块使用独立的普通福利QQ、邀请接收开关和月卡码池，签到、抽奖开关不控制邀请活动。

被邀请人的QQ账号等级必须严格大于10；同一被邀请人在整场活动的所有群中仅奖励一次，邀请者邀请不同合格新人可多次获奖。普通审批不能证明邀请归属，归属不明或等级未知不自动发奖。奖励为所选订阅分组的30天兑换码，同组兑换延长时间，不同组分别持有订阅。

先保存活动并确认订阅分组，再手动生成或预检导入同分组的未使用30天码（每批最多500张，无自动补库存），同步现有群成员基线。库存就绪后启用活动，再打开“启用邀请奖励接收”并保存；QQ在线本身不代表活动已启用。

订阅分组仅允许当前及保存后均停用、从未启用、无任何库存且无邀请/入群历史的草稿修改。曾启用后暂停或已有库存、历史的活动需新建活动换组。只改订阅分组保留成员基线，改变QQ群范围须重新同步。版本冲突需重新加载再编辑；分组锁定不能靠刷新解除，保存失败保留输入。

接入、升级和维护见[简明部署](../deploy/NAPCAT_QUICKSTART.md)与[完整指引](../deploy/NAPCAT_SETUP.md)，最新发布及部署状态见[当前交接](HANDOFF.md#当前代码和发布状态)。

## 账务与恢复

福利奖励使用整数分，消费进度保留 PostgreSQL `NUMERIC(20,8)` 精度；金额 API 使用十进制字符串。对账事实、签到和操作结果为追加记录，原始事实禁止修改／删除。

签到按用户与业务日期唯一，抽奖与兑换按账户、类型及幂等键唯一。用户资金变更在一个数据库事务中提交，失败整体回滚；服务端重试返回已保存结果。

兑换报价使用福利余额专用版本。消费进度变化不会令报价失效，其他领奖或兑换导致福利余额变化时需重新报价。

账户入账后的计费缓存和 API Key 认证缓存立即尝试失效，失败由持久 outbox 重试。余额缓存回填使用版本校验，防止兑换前的旧读取回填覆盖新余额。

内部费用修正接口 `RefundWelfareUsageBalance` 必须在调用方的 SQL 事务中使用，并关联原消费、有效管理员、理由及幂等标识。它不提供用户退款入口。已消耗的抽奖次数不回滚，退款后不足的资格由后续消费抵扣；退款和普通充值退款不是同一业务。

## 验证与性能

开发工具、前后端工作目录和可执行命令以[开发指南](../DEV_GUIDE.md)为准。每次 PowerShell 调用先加载主项目 `tools/project-env.ps1`，使测试日志、临时文件和依赖缓存留在 E 盘项目 `.cache`；复用已有 pnpm／Go 缓存，不因复核文档重新安装依赖或改锁文件。

按实际改动选择福利 service／handler、repository 集成、迁移和前端福利专项。数据库集成测试使用隔离数据库，不连接生产；默认容器入口需要 Docker，使用前核对其宿主存储位于 E 盘。检查输出确认测试实际执行，不能把容器不可用导致的 skip 当作通过。本机独立 PostgreSQL 替代测试入口的使用范围见下方带日期验证记录。

`TestWelfareBillingPerformanceSmoke` 对同一账户和多个账户分别运行关闭／开启福利时的结算，对比吞吐及 p50/p95/p99。它是本地小样本对比，不是生产承载能力保证。上线观察结算队列、数据库锁等待、WAL／IO、连接池和错误率，不能仅以接口平均响应时间判断影响。

关闭获奖开关可以停止新增奖励，但不会删除资金、历史记录或消费事实；不要用删除福利表的方式回滚已发生的活动。

历史初版的并发回归、页面对账与本地性能样本见[2026-09-19 开发与验证记录](WELFARE_CENTER_VERIFICATION_2026-09-19.md)；后续验证分别见[签到 v3](changes/2026-10-26-welfare-checkin-v3.md)、[抽奖 v4](changes/2026-10-27-welfare-lottery-v4.md)及[0.2.18-r2 发布记录](../deploy/CUSTOM_IMAGE_0.2.18-r2.md)。这些结果各自对应记录中的源码与环境，不代表本次文档更新重新执行了测试。
