## 2. 最终业务规则与已确认的问题

| 项目 | 当前行为 |
| --- | --- |
| 管理员配置 | 在订阅分组设置有限的正数日额度，并开启 `allow_subscription_day_reset`。 |
| 已购买月卡 | 同一分组的有效老月卡也使用当前分组限额并获得重置权限，无需重新购买。 |
| 用户自动开关 | `auto_daily_reset_enabled` 默认关闭。管理员授权不会替用户开启；已有的开启偏好会保留。 |
| 手动重置 | 当前日用量大于 0 且符合资格即可，不要求用满。 |
| 自动重置 | 用户主动开启后，仅在日用量达到或超过当前日上限时触发。 |
| 重置代价 | 每次成功将日用量清零，同时减少恰好 24 小时订阅有效期；扣后必须仍未到期。 |
| 次数限制 | 每张订阅、每个系统自然日最多成功 100 次。同一订阅的多把 API Key 共享次数。 |
| 周/月额度 | 已用额度和历史记录保留；周或月额度用尽时，不允许付费重置日额度。 |
| 自然刷新 | 按配置时区的日历日刷新，不扣有效期、不计付费重置次数。跨日后的请求或状态维护按新日界线更新额度。 |
| 默认零点 | 默认 `Asia/Shanghai`，即北京时间 00:00。Docker 默认配置为 `TZ=Asia/Shanghai`；实际部署如覆盖该配置，则按覆盖后的时区计算。用户所在地不决定日界线。 |
| 自动执行 | 开启后立即检查，结算后、请求准入时也检查；后台启动即扫描，之后每 30 秒扫描一批，无需保持网页打开。扫描间隔不代表所有订阅都保证在 30 秒内完成。 |
| 续费与暂停 | 未到期续费保留自动偏好；过期重新开通关闭自动偏好。单纯延长有效期不解除暂停状态。 |
| 断线与并发 | 使用事务、版本和操作 ID 防止重复扣天；浏览器恢复时先核实原操作，未确定前不另建扣天请求。 |

这里的“月卡”按 `subscription_type=subscription` 和管理员分组许可识别，不按套餐名称、价格或剩余天数推断。自然日刷新与“扣一天有效期换取当日额度”的手动/自动提前重置是两项独立行为。
