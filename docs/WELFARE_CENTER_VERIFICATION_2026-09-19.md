## 本次收尾

- 补齐服务器清理测试的福利 outbox 参数，并允许最小依赖清理时该任务为空。
- 修复兑换后的新余额查询加入兑换前旧查询的问题；按共享 Redis 代次隔离并检查回源结果，限定重试次数，Redis 故障时读取新的数据库快照。
- 对低于准入门槛的缓存余额强制复核数据库（含非零最低余额配置），防止旧异步扣费任务迟到后重复扣低兑换后的缓存快照。正常可准入缓存命中不增加数据库读取；持久层账务不受此缓存修复影响。
- 修复切换账号时旧未决操作恢复请求导致按钮长期禁用的问题。
- 流水类型、日期、页码与 URL 同步，支持恢复、浏览器导航以及非法参数清理。
- 抽奖/兑换幂等键兼容缺少 `crypto.randomUUID` 的 HTTP 环境，响应丢失后的重试继续使用原键。
- 增加真实采样器的完整概率分布和确定性成本验证，补齐未来奖励金额不泄露的响应契约。

## 2026-09-20 提交后复审修复

对 `9d8e5aa7f` 的独立复审确认并修复三项新增问题，以及影响福利功能的既有 CORS 遗漏：

- 同账号资料刷新只更新资料，不再触发福利会话重置。兑换输入、在途请求与成功提示保留；用户 ID 或会话确实变化时仍取消旧请求并清理私有状态。
- 余额缓存版本连续变化时，三次校验重试后单独读取一次新的数据库快照，不加入旧 singleflight、不回填缓存。正常竞争不再触发全局计费熔断；余额不足及最低余额限制仍有效，真实数据库故障仍按既有规则熔断。
- 福利可用性查询失败向公开设置和 HTML 注入层传播，页面走既有无配置注入的降级分支，避免把未知状态永久缓存为关闭。查询恢复后的下一次页面请求可恢复入口；明确关闭和未配置 provider 仍可正常缓存。
- CORS 对已经允许的来源放行 `Idempotency-Key`，使跨域抽奖和兑换可通过浏览器预检；不增加允许的来源。

以上问题均先添加可失败的回归测试，再修改实现。另同步两项旧嵌入页面测试的静态资源：项目实际使用 `logo.svg`，测试仍引用已不存在的 `logo.png`；保留状态码、图片 MIME 和缓存断言。

## 2026-09-20 修复 1122cd971 的四项审查问题

本轮复审确认一项最新提交回归及三项福利初版遗留问题，均已补充先失败后通过的永久回归测试：

- 计费准入只把真正的依赖错误计入熔断。与调用方上下文匹配的取消/超时不增加失败次数，也不清除之前的真实故障记录；余额和订阅准入采用一致处理。半开探测结束时按恢复轮次归还额度，旧请求不能增加新轮次的额度。数据库自身超时、取消或连接错误仍正常触发熔断，余额 generation 校验不变。
- 抽奖或兑换的未决请求重试遇到限流、认证或其他未知 4xx 拒绝时，保留原幂等键和请求体；确定业务结果才解除。新增测试模拟首次抽奖已提交但响应丢失、第二次被限流、第三次重试，确认只产生一笔操作；覆盖刷新页面后的按键查询恢复。
- CSP 的 iframe 来源独立读取主页、购买开关/链接和自定义菜单四项配置，不再依赖福利可用性。HTTP(S) 过滤、去重、管理员菜单来源和购买开关保持有效。福利查询失败仍阻止未知公共配置注入，但配置内的 iframe 来源在失败及恢复期间均有效。
- 兑换页面重试明确返回报价过期后关闭并重建弹窗，再打开可输入金额并获取新报价；未知或限流结果继续保留未决请求。弹窗锁定依据实际 pending 状态，首次请求被限流时可直接编辑；账号切换后的旧响应不能重置新账号弹窗。
