# 福利中心开发与验证记录

基线：`f89835007`（上游 v0.2.5 与已有月订阅修复）。开发分支：`codex/welfare-center`。2026-09-19 恢复上次中断的开发，2026-09-20 完成本地实现、审查与验证。

## 交付范围

已接入用户福利中心、管理员福利开关、独立福利钱包、北京时间签到及 7/15/30 天里程碑、确认的 v2 日奖、消费满 $50 抽奖、部分/全部兑换、日期/类型筛选流水。

福利迁移为 `239_welfare_center.sql`，使用仓库 SQL 事务实现；不为仅由 SQL 使用的表生成多余 Ent 模型。原计划的文件拆分被合并为领域、服务、仓库等文件，验收以行为为准。

发奖默认关闭；暂停不限制既有权益查询和兑换。未提前向用户展示签到金额范围或里程碑金额。兑换不增加累计充值，不触发邀请返利。

## 本次收尾

- 补齐服务器清理测试的福利 outbox 参数，并允许最小依赖清理时该任务为空。
- 修复兑换后的新余额查询加入兑换前旧查询的问题；按共享 Redis 代次隔离并检查回源结果，限定重试次数，Redis 故障时读取新的数据库快照。
- 对低于准入门槛的缓存余额强制复核数据库（含非零最低余额配置），防止旧异步扣费任务迟到后重复扣低兑换后的缓存快照。正常可准入缓存命中不增加数据库读取；持久层账务不受此缓存修复影响。
- 修复切换账号时旧未决操作恢复请求导致按钮长期禁用的问题。
- 流水类型、日期、页码与 URL 同步，支持恢复、浏览器导航以及非法参数清理。
- 抽奖/兑换幂等键兼容缺少 `crypto.randomUUID` 的 HTTP 环境，响应丢失后的重试继续使用原键。
- 增加真实采样器的完整概率分布和确定性成本验证，补齐未来奖励金额不泄露的响应契约。

### 本地页面账务样本

使用独立 PostgreSQL/Redis 容器、`127.0.0.1:58089` 和虚构测试账号，未使用生产数据库。浏览器签到实际获得 $0.06，账户余额仍为 $20；部分兑换 $0.01 后账户为 $20.01、福利为 $0.05。抽奖资格由独立测试 fixture 提供（真实扣费接入由数据库集成测试验证），抽奖实际获得 $1；暂停活动后兑换剩余 $1.05，账户最终 $21.06、福利为 $0。

数据库复核：累计福利发放/兑换均为 106 分，福利流水净额为 0，签到 1 次、抽奖 1 次，待完成缓存失效事件为 0。规则弹窗未预告未来签到和里程碑金额，已到账结果正常展示。
