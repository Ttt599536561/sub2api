## 确认的问题

| 编号 | 问题与影响 | 修复范围 | 回归证据 |
| --- | --- | --- | --- |
| REVIEW-01 | 复制分组遗漏 `AllowSubscriptionDayReset`，已授权的月卡副本会静默失去重置许可。 | `admin_group_duplicate.go` 复制该字段，同时保持来源为 false 时仍为 false、副本 inactive 和幂等复制行为。 | 新复制用例先复现 expected true / actual false，再通过；同时覆盖 true/false 和重复操作。 |
| REVIEW-02 | 自动扫描在处理前推进整页游标，25 秒超时会跳过尚未处理的订阅，直到全部分页回绕才恢复。 | `subscription_daily_reset_service.go` 在全部 worker 完成且 context 未取消后才提交游标。 | 虚拟时间准确推进 25 秒，旧实现将游标从 500 错误推进到 600；修复后保持 500，下一轮覆盖剩余候选。 |
| REVIEW-03 | 只监听“是否已登录”，忽略 A→B 且始终已登录的身份变化，旧订阅缓存和迟到重置响应可能进入 B 的页面。 | `App.vue` 同时监听用户 ID，在身份改变时清理各用户域状态，再加载新账号数据。 | 使用真实订阅 store 的 App 用例先出现两项失败；修复后验证切换、旧付费响应隔离和同用户资料刷新不额外请求。 |
| REVIEW-04 | `Date.parse` 丢失数据库时间戳的微秒；同版本、同毫秒的较旧消费快照可能覆盖较新的用量和控件状态。 | `subscriptions.ts` 在毫秒相同的情况下比较 RFC3339 小数精度。 | 普通列表和活跃列表两个乱序用例先复现 60 覆盖 70，再验证较新快照被保留。 |
| REVIEW-05 | 公告的迟到读取/已读操作、旧弹窗定时器可能改动新账号状态；批量已读等待期间新出现的公告也会被误标已读；组件还会保留旧详情或显示旧操作反馈。 | 公告 store 的身份代次隔离、已读回写范围，以及 `AnnouncementBell.vue` 的身份和卸载保护。 | 实际 store 的受控 Promise、定时器、新增公告用例，加上真实组件的身份往返、旧详情和反馈回归。 |
| REVIEW-06 | 管理员合规读取或接受操作的迟到响应会覆盖新账号状态，旧 finally 可能清除新请求的加载标记；对话框消费旧返回值时仍可能提示成功/错误并清空新账号输入。 | 管理员合规 store 的身份代次隔离，以及 `AdminComplianceDialog.vue` 的输入和异步回调隔离。 | 实际 store 的迟到 fetch/accept、加载状态回归，以及组件中的账号切换、A→B→A、注销和卸载回归。 |

这些问题并非都由此次 Git 合并引入：REVIEW-01 是二开字段遗漏在复制路径中的整合问题；扫描器和精度问题属于二开逻辑边界；登录和其他 store 的异步隔离缺口也存在于既有行为中。文本冲突为零不等于不存在这些运行时问题。
