## 已确认并修复的问题

### R21：确定未发送的建连失败也被禁止换号

上一轮未知创建结果 guard 会把初始 TCP 建连拒绝也当作可能已创建，从而返回 502，即使有健康备用账号。本轮真实 HTTPUpstream 回归确认错误为 `net.OpError{Op:"dial"}`，备用账号 200 的断言先失败。

现在用 `httptrace` 记录是否写出 headers/request，只有本次 POST 从未写出且错误明确为 dial 才标记 `RequestNotSent`。不能只看错误类型：POST 已发送后，307/308 重定向的后续 dial 失败仍属于未知结果。新增控制回归保证它不会触发第二次创建。

### R22：未知创建结果经过串联网关后又被重试

内层网关的未知结果原先只是普通 HTTP 502，外层会按普通上游拒绝换号重试，仍可能创建三份缓存。两/三层真实 handler 加本地 TCP 回归覆盖响应丢失及 2xx 不可用响应。

新响应头 `X-Sub2api-Cached-Content-Outcome: unknown` 贯穿支持此约定的网关；服务层仅在账号声明 `explicit_cache_upstream`、POST 且非 2xx 时识别，并以独立错误标记阻止换号。发送前失败、普通 401/403/429/503、未声明账号和其它方法的处理保留。

串接部署时，各层需包含本修复并保留该响应头；旧网关或移除响应头的中间层不能提供这项跨层识别。首个响应未知的资源仍可能存在，本修复不声称已清理其未知资源名。

### R23：候选身份与到达顺序导致主候选结束状态错位

新 metadata 合并器原本用数组位置代替缺省 candidate index，且保留到达顺序。次候选先出现时，省略 index 的主候选可能被重复登记；明确 index 0 的正文也可能被放到次候选后，使 `MAX_TOKENS` 变成 `end_turn`，或主候选 `SAFETY` 信号被遗漏。

缺省 index 现按 0，按真实 index 稳定排序。回归覆盖省略/显式 0、主候选终止信号，以及公共 direct/wrapped、Antigravity Gemini/Claude 路径。相同明确 index 用例使用父提交两个 collector 文件的 overlay 对照通过，确认这是上一轮合并器引入的回归。未扩展完整多候选正文聚合功能。

processor 已发出 `message_stop` 后，服务仍等待 EOF；后续连接错误会再发送 error 并丢弃已完成的 usage，或持续等待未关闭的 body。这是相关调用链保留的旧缺口。

服务在 processor 确认 `[DONE]` 已结束消息后立即关闭上游并返回累计用量。仅有 `finishReason` 时仍等待后续 usage。回归覆盖 DONE 后错误、连接不关闭时及时返回/关闭/解除阻塞读取，以及没有 DONE 时真实错误仍须返回。现有迟到用量及断线 drain 语义保持。
