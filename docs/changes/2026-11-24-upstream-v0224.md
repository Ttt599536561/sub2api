## 合并中修复的问题

- **订阅与余额结算**。同用户的批处理逐笔执行基础额度与补充额度分配，按期次处理旧请求并释放持久预占。余额批扣逐笔累计福利消费。重复请求继续使用既有幂等记录。API Key 限速合计以十进制定点值写库，在十亿级基数上叠加 0.00000001 仍与逐笔记账一致。
- **协议转换与计费**。缓存读取与写入可分别出现在两个明细对象中。转换保留有效计数、TTL、音频、推理和预测明细，显式写入零不能在下一次转换后变成收费数量。流式和缓冲响应采用相同的终态用量优先级。
- **模型路由与价格**。保留 OpenAI 分组全模型强制 UltraFast、与 Fast 互斥及固定 8 倍的二开策略，Composite 分组仅支持强制 Fast。校正渠道自定倍率的优先级。Messages 通过透传账号转换时以实际出站模型检查供应商，原请求的模型过滤规则继续生效。
- **退款和视频任务**。支付宝按订单与金额生成跨重试稳定的请求号，保留不确定退款的待确认状态。Grok 视频创建保留延迟发布任务 ID 机制，同时正确向客户端返回输入校验错误。
- **管理界面与配置**。兼容 Bedrock 开关的历史对象和现行布尔值。账号切换时按当前组和实际模型过滤本次请求头，后备账号仍能取得原始 Beta 头。修复编辑分组时丢失价格倍率、刷新时隐藏已有配额的问题。保留 r7 的账号用量隔离和上游新增观测数据。
