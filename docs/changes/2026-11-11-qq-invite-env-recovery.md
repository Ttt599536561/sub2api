# 面板重建后的邀请环境恢复

日期：2026-11-11（Asia/Shanghai），最终外部核验16:19。用户更新0.2.21-r1镜像后，福利管理提示邀请奖励加密密钥未配置，并要求使用既有腾讯云SSH连接处理。

## 原因与实际修复

只读核实发现：Sub2容器已是0.2.21-r1且healthy，但创建来源只有主Compose，缺少QQ_INVITE_ENCRYPTION_KEY和NapCat网络。原napcat/sub2api.env中的密钥格式有效、文件完好；NapCat/PostgreSQL/Redis均正常。邀请模块从r3到r1相关源码无差异。

原生产overlay保存了邀请env_file引用和网络优先级；面板只按主文件重建时遗漏了这些附加项。本轮先在服务器私有目录备份原主Compose、overlay及环境文件，再将Sub2所需env_file和网络配置纳入主Compose。NapCat服务本身仍保持原overlay定义，避免重复security_opt；主文件单独解析与原生产合并结果的对应服务完全一致，再叠原overlay也与旧完整配置完全一致。保留变量引用，未把邀请密钥展开写入主文件。

仅以现有镜像重建Sub2应用，未拉取新镜像，未重建依赖。执行前确认没有held生图订单或sending邀请发件；没有执行数据库修改、初始化、密钥轮换或QQ消息发送。

- 原邀请密钥已在Sub2进程加载；原密钥文件和生产overlay哈希不变。
