# 单用户邀请福利月卡管理调整

用户要求后台可针对个别用户的邀请月卡调额度和天数，明确输入“月卡总额度”：总额50、已用20时剩余30。操作只影响该用户当前福利周期，不调整全组、普通付费订阅或既有用量。

## 规则与实现

- 在后台订阅管理的福利记录提供专用“调整邀请月卡”入口；原普通延期、重置、恢复的隔离继续保留。
- 总月额度和剩余天数可独立勾选。金额为非负、最多两位小数；0额度明确禁止继续使用，不解释为无限。天数按保存时起算，0天立即到期；不填写的字段保留原值。
- 调低总额度可以低于已用量，剩余展示取0；已用量、窗口、历史授予流水不清零。手动延长福利周期也不触发30天月额度刷新。
- 仅允许调整未撤销、未关闭的active/expired福利记录；关闭旧周期不能重新激活。过期但未关闭的周期如手动延长，保留旧用量。新邀请码仍按原规则正常累加或开启新周期，此功能不是永久禁止用户领取。
- 必填调整原因。操作人/管理密钥取自鉴权上下文，持久审计与权益更新同事务，审计失败全部回滚。精确更新字段，避免覆盖并发消费。
- 锁定订阅后核对管理版本（复用daily_reset_version）与已领取张数，防止旧表单覆盖新兑换或其他调整；幂等键隔离重复提交，冲突需要显式重载，不自动覆盖用户输入。
- 新权限`subscriptions.welfare.adjust`独立于普通延期权限，受限密钥响应仍按读取权限裁剪。
- 新增257迁移，只放宽福利月额度允许0并建立调整审计表；普通分组0表示无限的语义保持。新发放福利码仍要求正的月额度。
