## 复审确认与本地修复

### V217-R1：pending 订阅退款恢复与二开撤销语义冲突

上游默认通过 ExtendSubscription 归还天数，但二开退款可能软删除整个订阅，或需要按原有效期准确加回扣减；直接拼接会找不到软删除记录、错误增加有效期，且审计失败时不能同事务恢复。pending 审计现在保存本次撤销的 ID、用户/分组、删除/更新时间和 dailyResetVersion，失败归还使用已有精确恢复并复用外层事务；管理员后续撤销不被覆盖，提交后再次失效缓存。旧 pending、已确认网关成功后的恢复和福利一致性分别回归。

### V217-R2：支付 SDK 页面缺少登录归属

Stripe 和 Airwallex 公共支付路由不会在所有换号/重新登录情况下卸载；只检查 disposed 会允许迟到 SDK/订单请求继续使用旧 client_secret，回填旧订单、二维码或错误，并继续跳转。两页改为沿用已有支付流程的会话身份函数，同页 auth watch、跨页 storage 和各异步边界均核验；失效清私密 UI、停止轮询/计时器、销毁 Stripe 元素，保留合法签名恢复与共享快照。Stripe 新增上游测试的快照补齐二开 owner 夹具，不降低生产归属检查。

### V217-R3：WS 实际发送的退役模型漏拦

渠道别名和账户映射在不同 WS 模式的处理不同。旧支持性检查可能把一个别名或残留账户替代映射当作可用，随后向 ChatGPT OAuth/SetupToken 实际发送退休的 gpt-5.5；首轮与后续轮都可触发。新检查在最终实际 wire 模型确定后执行，拒绝属于本地路由错误，不惩罚账号、不重放请求。原生模式的有效账户替代映射及 API Key 请求仍允许，HTTP passthrough 的既有精确解析单独验证。

### V217-R4：易支付金额确认接受 NaN/Infinity

`ParseFloat` 可以成功解析字符串 NaN/Infinity，差值比较遇到 NaN 返回 false，导致本应拒绝的金额确认成功。新增显式有限值检查，五个输入场景先 RED 再 GREEN；保留正常金额、交易号与订单身份确认。
