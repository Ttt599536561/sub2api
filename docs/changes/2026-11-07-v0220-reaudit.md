## 确认缺陷与修复

1. **P2：CSV导出跨会话混入数据。** 上游新增429等待重试未绑定发起会话；A导出第1页后，第2页429，退出并登录B或卸载页面，旧定时器仍可用B凭据继续分页并合并两者记录下载。真实组件与Axios回归取得RED。绑定页面owner、每页派发/响应/重试/下载前检查；卸载/会话失效时取消请求及等待。正常同会话token刷新仍允许完成导出。
2. **P2：停用/降级的旧快照漏撤销MCP。** 用户更新在拿行锁前读取existing，再依赖old/new差异决定撤销。并发恢复与授权插入后，旧写入可能认为状态没有变化而漏撤销；恢复后授权重新可用。真实PG确定性RED。显式写入非active状态或非admin角色时，依据实际写入结果撤销对应授权，不依赖过期existing快照，保留事务回滚。
3. **P2：撤销全部MCP授权漏掉在途同意。** 撤销只更新现存grant，已读取用户快照的同意请求可在撤销返回后插入可用grant。真实PG确定性RED。撤销事务先锁用户并单调推进微秒精度updated_at，使旧同意快照失效，再用独立SQL语句撤销授权，确保锁等待后可见刚提交的grant；保持user→grant锁顺序。未改JWT全局失效设计。
4. **P2：原生Anthropic首事件失败仍按次计费。** 非流式Responses/Chat桥接上游SSE，在200后的首事件直接error、无message_start或usage时，上游新增错误分支返回非nil零用量result，按次价格仍结算一次。两条路径各$2的错误扣费已RED复现。仅尚未开始响应且用量全零的失败返回nil；已开始/已有用量的部分处理仍保留结算，补中途失败正向边界。
