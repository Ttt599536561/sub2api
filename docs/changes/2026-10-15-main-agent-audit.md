## 发现并修复的问题

### P1：固定费用预留与实际结算使用不同价格

`QuoteUsageCost` 先计算预留金额，`RecordUsage` 在上游请求结束或异步 worker 执行时重新读取价格及用户倍率。定价热更新时，两次计算会产生不同金额。独立回归复现：预留 **$0.01**，更新存储价格后实际扣款 **$0.10**。

修复为保存不可变费用快照，包含费用构成、倍率、计费模型、时点和存储量；创建、续期和保存失败后的输入费用结算传递同一快照。上游提前到期或清理失败缓存时，只按原价格减少存储费用，不改变输入费，也不修改原快照。普通没有固定报价的网关调用保留原计费流程。新回归还通过 handler 验证上游执行期间倍率变化不会超出预留。

### P2：分组批量 API 未绑定操作发起时的登录会话

分组 API 没有在 Axios 拦截器排队前捕获归属（首先在倍率和 RPM 的读取、清空、批量保存方法复现），换号/同账号重登后可能用新凭据发送旧操作；成功回包也没有归属复核。新增 12 项 API 回归，修复前全部失败。

修复统一覆盖分组 API 模块的 28 个公开操作（26 处直接 HTTP 调用），包括创建、修改、删除和复合路由；最终 56 项 API 回归通过。这些入口现在绑定现有的 `sessionID/userID`，派发前检查沿用原拦截器，返回数据前再检查归属；不把会话标记放入 HTTP body。用户搜索支持传入同样的请求归属选项。

### P2：旧分组弹窗操作污染新表单

原保护只覆盖加载；保存完成会关闭重新打开的弹窗，旧保存失败会释放新保存的忙状态，RPM 清空回包会清空另一个分组的显示，搜索回包/定时器也可越过查询、关闭和登录边界。

两个弹窗复用管理员弹窗会话边界，覆盖分组、打开周期、卸载和登录身份；所有异步完成、错误与 finally 均检查归属。搜索绑定输入时的查询和序号，关闭后取消未派发任务。还补测了浏览器 storage 事件尚未送达时直接点击旧草稿的情形：此时必须拒绝，不能只依赖事件回调。

上述 API 与弹窗问题在合并前已有部分缺口；本次检查了合并触及的组件及关联调用链，没有把继承问题全部归因为本次文本合并。

### P2：模型目录读取失败仍被当作成功

本轮模型接口路径中的 `doGeminiModelsGET` 忽略 `io.ReadAll` 错误，传输中断可能返回部分响应体及成功状态。故障注入回归用 `io.ErrUnexpectedEOF` 复现了“应返回错误却返回 nil”。现在返回带原因的读取错误并关闭响应体，不再转发不完整的成功目录。这是新路径继承的错误处理缺口。
