## 问题与修复

### WebSocket 无响应 ID 的多轮计费

旧实现跳过无 response.id 的逐轮回调，最终统一结算；任一轮缺失 TTL 会令会话分解未知，覆盖已知 12h 轮的溢价。实际复现：第一轮一百万 12h 写入，第二轮一百万未知 TTL 写入，应合计 $0.375，实际 $0.250；真实 ID 对照正常。

修复以已接受的 response.create 界定轮次，无响应 ID 也逐轮结算；创建阶段及终帧中迟到的真实 ID 关联同一轮的时刻、模型及档位。匿名轮得到连接随机标识与轮号组成的内部计费 ID，避免共享连接 ID 造成去重漏扣；上游真实 ID 和客户端报文保持。重复终止事件在用量累加前隔离，保留 error→failed 延迟结算规则；未知 TTL 仍按通用价，不伪造为 30m。防重复需同时匹配计费与请求准入生命周期。

### 主动查询后的配额缓存

旧实现主动查询只更新显示状态，父页面五分钟缓存仍是旧值；真实分页复现 100%→主动查询25%→切页返回100%，没有新查询。

成功网络结果同时更新对应父/子缓存，并使较早批量请求失效；缓存/props回放不再作为网络成功事件，避免缓存 TTL 被不断延长。数据接纳检查账户、类型、浏览器会话、来源及请求序号；loading 清理按当前请求序号判断，避免会话切换或请求被替代后按钮锁住。失败保留有效配额，手动刷新仍强制请求。
