# v0.2.21 合并审查问题修复

日期：2026-11-11（Asia/Shanghai）。基线为本地主目录 main 的合并提交 `6a267950704255938818bda7af64e26563642734`。用户要求修复本轮审查确认的两项问题；本轮仅本地修改、验证和提交，不推送 GitHub、不发布镜像、不部署或操作真实业务。

## 已确认的问题

1. OpenAI 兼容 HTTP 与 WS-v2 路径丢失 30m/12h 缓存写入明细，12h 写入被按通用价格结算。审查阶段原生 Responses 对照通过，兼容接口及真实 WS 转发到 RecordUsage 的测试失败；gpt-6-luna 的一百万 12h 写入缓存费应为 $0.25，实为 $0.125。
2. Antigravity 初次用量查询网络失败后，点击“查询”成功返回额度仍显示旧错误：loadActiveUsage 只更新 usageInfo，未清 error；模板错误分支优先于额度展示。

## 修复范围

- HTTP：终帧直接读取所选原始 usage，保留各路由原有 usage 来源优先级；全零或缺失终帧不清除先前已观测的有效用量，与原生 Responses 保持一致。类型化 Responses/Chat 转换保留 TTL 原始字段；input/prompt 混合别名仅在 input 缺失 TTL 字段时回退，显式 null/非法值不回退，并验证最终费用、用户扣款、日志及账户成本。
- WS-v2：覆盖解析、当前轮快照更新、逐轮终止结果、会话累计与两处适配器。实际按轮保留有效明细并结算；会话汇总仅在每个有写入的轮次均有完整分解时累计 TTL，任一轮未知则汇总分解保持未知，不把未知写入猜成 30m。无 response.id 的会话兜底也覆盖。
- 前端：成功查询恢复错误状态；失败查询保持原有可用数据。
- 不更改数据库迁移、已有价格配置、倍率或历史用量记录；修复对新请求生效，未自动追补历史费用。
