# 单笔购买订阅套餐赠送抽奖次数

用户确认：单笔实际支付人民币每满50元送1次，恰好50元送1次，200元送4次。不同订单独立计算，余数不跨单累计。

## 规则

- floor(pay_amount / 50)：49.99元0次、50元1次、99元1次、100元2次、200元4次；两笔25元0次，两笔75元2次。
- 使用订单支付币种快照及实付金额，仅人民币订单参与本次规则，不用美元套餐价或当前汇率换算。
- 套餐赠送独立整数次数，不写入API美元消费eligible_spend；原API实际余额消费累计规则保留，两种来源的整数次数可共同使用。
- 上线后首次完成履约时计算。福利必须已开放且未暂停，付款时间不得早于福利首次开放。历史已完成订单不补发；充值、赠送订阅、兑换码及订阅额度内使用不额外赠送。
- 订单完成与赠送在同一个数据库事务中，重复通知和重试不得多送。
- 退款确认后按该订单剩余净实付人民币重新计算，回退差额：200元退60元，净140元保留2次。待确认/失败退款不回退。
- 已中奖余额不收回；已用次数不足扣时形成已有待抵扣次数。退款不重复回充账户余额。

## 实现

新增welfare_wallets.subscription_draws及订单唯一的welfare_subscription_rewards表，保存原实付/赠送/已回退和退款金额。保留旧welfare_spend_events审核约束。
WelfarePaymentRepository要求Ent事务，按订单→用户→钱包顺序锁定。支付完成及退款状态与权益原子提交；网关确认退款但本地失败时保存可重试的本地收尾状态。
前端分别描述套餐单笔人民币规则与API余额累计美元规则。

## 验收

真实数据库验证单笔阈值、不跨单、币种/金额快照、并发幂等、回滚、历史及开关、全额部分退款、无原赠送、欠额、余额不变。服务验证完成与退款事务/恢复；前端测试和构建；独立规格及质量复核。
