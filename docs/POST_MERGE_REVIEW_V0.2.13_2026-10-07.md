| TypeSafe Windows CMD 示例 JSON 无效 | 模板字符串吞掉转义反斜杠，复制到 CMD 后 curl 接收的 JSON 丢失属性引号。 | 保留输出中的反斜杠；跨平台静态检查及真实 Windows CMD 参数解析均验证。测试使用本地 argv 记录器，无外部请求。 | 官方 0.2.12 新增示例缺陷。 |

最后独立复核额外发现并关闭了两个边界：退款恢复计划生成后发生并发状态变化，以及手续费按浮点数计算导致上限误判。前者增加原始计划状态保护；后者使用原金额/费率的十进制系数，以 BigInt 复现 `backend/internal/payment/fee.go` 的 16 位除法中间舍入及最终向上取整，不用固定 epsilon 吞掉真实分厘。支付币种采用后端 `currency.go` 的零位/三位/默认两位映射，避免 Intl 对 IQD/CLF 等币种给出不同精度；AmountInput 快捷金额和确认区共用该映射。未引入新依赖。

## 明确边界

旧版本普通 pending 退款审计没有保存管理员的扣款选择，零扣款也可能代表强制退款时余额不足，无法从现有历史数据可靠反推。本次为新操作完整保存意图；旧记录若明确标记 `deductionType=none` 则不扣减，否则保留既有兼容行为。处理旧 pending 订单前应核对当时的人工选择；本轮没有连接线上数据库或改写历史订单。

若网关已接受退款后数据库完全不可写，仍需要根据网关和审计恢复；本次不会在缺少持久化意图时假装完成收尾。真实支付网关、真实外部模型和真实浏览器多标签页联调不包含在本次本地自动化验证中。
